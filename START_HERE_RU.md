# Первый запуск Campus Flow

> **PR2:** уведомления, колокольчик, мобильное PWA и отдельный сервис объявлений. [Уведомления](docs/NOTIFICATIONS_RU.md) · [Установка на сервер друга](docs/DEPLOY_FRIEND_RU.md). Обычный запуск теперь без модели; для автоперевода включить COMPOSE_PROFILES=translation и TRANSLATION_WORKER=true. Новые бэкапы включают четыре БД.

## 1. Подготовьте папку

1. Скачайте ZIP и распакуйте его целиком: правая кнопка → «Извлечь всё».
2. Можно выбрать `C:\Projects\campus-flow`. В рабочей папке должны лежать `compose.yaml`, `START_WINDOWS.cmd`, `README.md` и папки `apps`, `services`, `scripts`.
3. Не запускайте файлы внутри окна ZIP: рядом должны сохраняться конфигурация и резервные копии.

## 2. Windows и Docker

Если Docker Desktop уже установлен, запустите его и дождитесь готовности движка. Нужен режим **Linux containers**, поскольку приложение использует Linux-образы Python, Nginx и PostgreSQL.

Если Docker ещё нет, используйте [официальную инструкцию установки](https://docs.docker.com/desktop/setup/install/windows-install/). Она содержит актуальные требования Windows, WSL и виртуализации. Docker поддерживает версии Windows, остающиеся в сроке обслуживания Microsoft; совместимость конкретной установки Windows 10 нужно сверить с этой страницей. Приложение также можно запустить на Linux-сервере.

Не нужно устанавливать Python, Node.js, PostgreSQL и Nginx отдельно для Docker-запуска.

1. Откройте папку `campus-flow`.
2. Дважды нажмите `START_WINDOWS.cmd`.
3. Первый запуск скачивает образы и зависимости. В окне будет идти сборка — дождитесь сообщения с адресом сайта.
4. Скрипт создаёт `.env` с уникальными случайными ключами, только если этого файла ещё нет. Повторный запуск сохраняет существующую конфигурацию.
5. Откройте **http://localhost:8080**. Адрес `localhost` работает только на этом компьютере.

Если открывали PowerShell самостоятельно, можно выполнить из папки проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Параметр ExecutionPolicy действует на этот процесс; системная политика не меняется. В управляемой организацией системе локальные политики могут запретить выполнение. Тогда используйте одобренный администратором способ запуска.

## 3. Linux

Установите [Docker Engine](https://docs.docker.com/engine/install/) и [Compose plugin](https://docs.docker.com/compose/install/linux/), затем из папки проекта выполните:

```bash
bash scripts/start.sh
```

Нужен `openssl` для создания ключей. Если ваш пользователь не имеет доступа к Docker, используйте установленный на сервере способ работы с Docker; например, запуск скрипта через `sudo bash scripts/start.sh`.

## 4. Создайте администратора

При первом открытии сайт покажет «Настроим вашу группу» / форму настройки группы.

1. В папке проекта найдите файл `.env`. Включите отображение расширений в Проводнике, чтобы не спутать его с `.env.example`.
2. Откройте его Блокнотом.
3. Найдите строку `SETUP_KEY=...`.
4. Скопируйте только символы после `=`. Не отправляйте весь `.env` в общий чат.
5. На сайте укажите свои ФИО, email, пароль длиной 12–128 символов и ключ первого запуска.
6. Нажмите кнопку создания администратора.

Первая учётная запись получает роль администратора. После неё повторное создание администратора через первый запуск закрывается. Email нужен как логин; отправка писем и автоматическое подтверждение адреса не подключены.

## 5. Настройте семестр

Откройте **Управление → Семестр**.

1. Проверьте группу `БВТ2302`, направление `09.03.01`, курс `4`.
2. Укажите настоящие даты начала и конца семестра.
3. Оставьте часовой пояс `Europe/Moscow`, если пары идут по московскому времени.
4. В поле опорного понедельника выберите начало недели, чётность которой вам точно известна.
5. Укажите чётность этой недели: чётная или нечётная.
6. Нажмите «Сохранить изменения».

Пример: если понедельник 31.08.2026 относится к нечётной учебной неделе, укажите эту дату и «Нечётная». Тогда 07.09 будет чётной, а 14.09 — нечётной. **Это пример настройки, а не утверждение о чётности в МТУСИ.** Сверьте с [официальным расписанием МТУСИ](https://mtuci.ru/time-table/). Каникулы автоматически не сбрасывают чередование.

## 6. Добавьте реальные пары

В **Управление → Шаблоны** нажмите «Добавить пару».

Заполните название, при необходимости английское название, тип (лекция / лабораторная / практика), преподавателя, день недели, повторение (все / чётные / нечётные), время начала и конца, формат, аудиторию, подгруппу и заметку. Для дистанционной пары можно добавить HTTPS-ссылку на конференцию.

**Английское название необязательно:** при включённом профиле translation пустое поле включает локальный автоперевод. Свой вариант имеет приоритет. Пока модель готовит перевод или недоступна, показано исходное название. ФИО, аудитории и пользовательские заметки автоматически не переводятся.

У лабораторной или практики можно включить «Очередь». Для лекций очередь отключена. Лимит по умолчанию — 30 участников, открытие записи не раньше чем за 24 часа до начала, оценка приёма — 7 минут на студента. Эти значения меняются в настройках конкретной очереди.

Два занятия не могут пересекаться для одной подгруппы. Пересечение допустимо для разных подгрупп. У пары «Вся группа» нет права пересекаться ни с одной из подгрупп.

Чтобы просто осмотреть приложение, в пустом разделе шаблонов можно загрузить примеры. Все они отмечены плашкой «Пример». После знакомства нажмите удаление примеров и заполните настоящие пары. Архивированные примеры остаются в истории, поэтому повторная загрузка демо после удаления не поддерживается.

## 7. Измените одну пару

1. Откройте «Расписание» или «Календарь».
2. Нажмите карточку занятия.
3. Нажмите «Изменить только эту пару».
4. Выберите другую дату / время, дистанционный формат или статус: подтверждена, ожидает решения, отменена.
5. Сохраните.

Изменение действует только на выбранное занятие. При переносе идентификатор пары и её очередь сохраняются. Очередь приостанавливается до проверки старостой и повторного открытия. При отмене активные участники снимаются, история сохраняется. Если отмену впоследствии отменить, прежние места сами не возвращаются.

Для изменения повторения на следующие недели откройте **Управление → Шаблоны → Изменить**. Прошедшие занятия и индивидуально отредактированные пары сохраняют своё состояние. Архивирование шаблона отменяет его будущие обычные занятия; индивидуальные исключения нужно проверить отдельно.

## 8. Пригласите группу и назначьте роли

1. **Управление → Участники → Создать приглашение**.
2. Укажите количество регистраций (например, 35) и срок действия (например, 7 дней).
3. Скопируйте код и передайте одногруппникам.
4. На странице входа студент выбирает регистрацию, вводит свои ФИО, email, пароль, код и подгруппу.
5. Его заявка появится в участниках со статусом ожидания.
6. Староста, заместитель или администратор сверяет человека и нажимает подтверждение.
7. Студент входит со своим email и паролем.

**Назначить старосту / заместителя может только администратор:** в участниках откройте «Изменить», выберите роль и сохраните. Староста и заместитель имеют одинаковые рабочие права на расписание и очереди; роли различаются обозначением. Они не могут назначать администраторов или менять руководящие роли.

Администратор также может вести пары и очереди. Один человек не обязан создавать себе отдельный аккаунт заместителя. Изменить свою роль или заблокировать себя через интерфейс нельзя; для этого нужен другой администратор.

## 9. Откройте очередь

1. Откройте карточку лабораторной.
2. Нажмите создание очереди, затем «Открыть очередь».
3. При необходимости измените лимит, время открытия и минуты на студента через значок настройки.
4. Студент откроет эту же пару, напишет, что будет сдавать, и нажмёт запись.
5. Участники видят текущую очередь и своё место. Обновление — каждые 4 секунды, пока вкладка открыта.
6. С начала пары староста нажимает вызов следующего. Система выбирает первого ожидающего.
7. После ответа нажмите «Работа сдана» или отметку отсутствия.

Все подробности: [правила очередей](docs/QUEUE_RULES_RU.md).

## 10. Смена темы, языка и пароля

**Настройки** содержит светлую, тёмную, чёрную, ультрачёрную и системную темы, русский / английский и изменение пароля. Тема и язык сохраняются на устройстве. Системная тема реагирует на изменение темы ОС. Смена языка не меняет состав расписания и очередь.

## 11. Что делать дальше

- Для других компьютеров нужен доступный адрес сервера; одного `localhost` недостаточно. Подробности в [инструкции размещения](docs/OPERATIONS_RU.md).
- Создавайте резервные копии перед изменениями и обновлениями.
- Git уже ведётся локально; инструкция выгрузки в ваш GitHub находится в [docs/GIT_RU.md](docs/GIT_RU.md).
- Файл [docs/VALIDATION_RU.md](docs/VALIDATION_RU.md) разделяет выполненные проверки и контейнерные проверки, которые ещё нужно прогнать в вашей среде или CI.
