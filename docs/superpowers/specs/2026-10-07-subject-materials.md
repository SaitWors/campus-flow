# Материалы предметов

Пользователь хочет хранить лекции, конспекты и прочие учебные файлы внутри Campus Flow. Он явно выбрал загрузку только руководством: admin/head/deputy. Подтверждённые участники читают и скачивают общие материалы; гости и неподтверждённые аккаунты не имеют доступа. Файлы принадлежат предмету, отдельные личные хранилища не добавляются.

## Поведение
- Страница предмета: раздел «Материалы», категории lecture/notes/other, поиск, постраничный список, размер/имя/дата/автор, скачивание, предпросмотр растровых изображений.
- Руководство загружает один или несколько выбранных файлов последовательно, редактирует название/описание/категорию и удаляет после подтверждения. Обычный студент не видит элементы управления загрузкой.
- По умолчанию один файл до 50 МиБ; всё хранилище до 5 ГиБ. Настройки MATERIAL_MAX_FILE_BYTES и MATERIAL_STORAGE_QUOTA_BYTES. Без новых внешних сервисов и платных зависимостей.
- Документы PDF/DOC/DOCX/PPT/PPTX/XLS/XLSX/ODT/ODS/ODP, TXT/MD/CSV; изображения PNG/JPG/JPEG/WEBP/GIF/HEIC; ZIP и записи MP3/M4A/OGG/WAV/MP4/WEBM. SVG/HTML/исполняемые файлы не разрешены. Растровые изображения проверяются по сигнатуре; остальные документы скачиваются как attachment. Исходные имена не используются для путей.
- Файлы передаются потоком, не загружаются целиком в RAM; временные/ошибочные файлы удаляются. Постоянный том только у schedule. Каждый просмотр/скачивание заново проверяет аккаунт. Нет общедоступного static/files, offline-кеширования и обхода авторизации через URL.
- Если браузер не получил подтверждение загрузки, включая ответ 500/503 после commit, файл помечается как имеющий неизвестный исход. Интерфейс предлагает проверить список и не повторяет этот файл автоматически.
- Схема schedule 5, остальные auth3/notifications3. Новая таблица материалов и строка блокировки квоты. Блокировка предотвращает превышение квоты при конкурентных загрузках.
- Резервные копии и перенос установки включают material-файлы; восстановление проверяет контрольные суммы и не извлекает произвольные пути/симлинки из архива. Старые копии без файлов принимаются только для схем до5. Старые данные и тома сохраняются; реальный сервер в этой задаче не меняется.

## API-контракт
Material = {id, subject_key, title, description, category: lecture|notes|other, original_filename, mime_type, size_bytes, created_at: UTC ISO, uploader_name, revision}.

- GET /api/schedule/subjects/{key}/materials?category=lecture&q=...&limit=50&offset=0 -> {items: Material[], total, limit, offset, storage: {used_bytes, quota_bytes, max_file_bytes}}. category необязательная; q до160, limit1..100. Сортировка новые первые; поиска по title/description/filename, без путей хранения.
- POST /api/schedule/subjects/{key}/materials?filename=...&title=...&description=...&category=lecture ->201 Material. Тело — сырые байты ОДНОГО файла, Content-Type=application/octet-stream, стандартный X-CSRF-Token. title1..160, description0..4000, filename1..240, category по умолчанию other. Для нескольких файлов отдельный запрос на каждый.
- PATCH /api/schedule/materials/{id} JSON {revision, title, description, category} -> Material. revision обязателен; конфликт409.
- DELETE /api/schedule/materials/{id}?revision=N -> {ok:true}; конфликт409, файл перестаёт быть доступным.
- GET /api/schedule/materials/{id}/file -> авторизованный attachment; ?inline=true только для PNG/JPEG/WEBP/GIF. HEIC скачивается. Content-Disposition с безопасным UTF-8 именем, nosniff/no-store и CSP sandbox. Нет внутреннего пути в ответе.
- Ошибки: material_too_large(413), material_storage_full(409), material_type_not_allowed(415), material_content_mismatch(415), material_empty(400), material_filename_invalid(422), material_unavailable(404), storage_unavailable(503). Права/CSRF используют существующие ошибки.

## Хранение и операции
MATERIALS_DIR=/var/lib/campus/materials в контейнере, default .dev-data/materials локально. Файл {uuid}.blob; staging {uuid}.part; временная OS-блокировка {uuid}.lock. UUID/path валидируются, симлинки не принимаются. После передачи файла потоку публикации только этот поток отвечает за commit/cleanup; отмена запроса не удаляет уже сохранённые байты. При старте сервис очищает разблокированные .part и .blob без записи в БД, проверяя ссылку после получения файловой блокировки. Инвариант API: видна только полностью опубликованная запись с файлом. Материал не генерирует уведомлений в этой задаче.

Архив материалов в копии: materials.tar; каталог только плоские UUID.blob файлы. Manifest и контрольные суммы записываются вместе с дампами при остановленных писателях. До замены рабочего тома/БД проверяются все файлы архива. Восстановление прежней копии без материалов требует пустого материала-тома, чтобы не оставить файлы от другой точки во времени. Тест восстановления выполняется в отдельном каталоге.

Файловые операции восстановления используют постоянную OS-блокировку и приватный подписанный журнал. Незавершённый receiving очищается только после получения блокировки и проверки владельца/содержимого. Прерванная публикация требует явного recover при остановленном приложении: он завершает проверенный файловый snapshot, сохраняет прежние байты и не меняет БД. Неизвестные каталоги и симлинки не удаляются. Production restore/test-restore отвергает копию без пригодных DB snapshots до любых мутаций; локальная копия восстанавливается своим скриптом. Для прямого запуска schedule и в Compose задан h11 incomplete-header лимит 64 КиБ, чтобы максимальные Unicode-метаданные принимались при фрагментации строки запроса.

## Проверки
Реальный HTTP: права/CSRF, кириллица, файлы >64КиБ, chunked превышение лимита, пустые/неверные типы, квота/конкуренция, пагинация/поиск, приватное скачивание/preview, редактирование/удаление/конфликты, повторный запуск и миграция4->5. Файловое хранилище: путь/симлинк, ошибки диска/DB, очистка .part. Операции: архив/checksum, безопасное извлечение, старые копии, roundtrip. Браузер: менеджер upload/read/edit/delete, студент read/no upload, гости denied, мобильные размеры и существующие функции.
