# Campus Flow: учебный кабинет без очередей

Цель: повседневный сайт группы с экраном «Сегодня», работами, страницами предметов и уведомлениями в браузере и Telegram. Пользователь явно исключил импорт расписания; очереди удаляются полностью из исходников и работающей топологии. Изменения выпускаются отдельным PR, без слияния и изменения рабочего сервера.

## Состав
- Экран «Сегодня»: текущая/следующая пара, время до начала, занятия на день, ближайшие сроки работ; учитывает часовой пояс семестра и подгруппу.
- Раздел работ: номер/название, предмет, условие, срок, ссылка на материалы, подгруппа. Студент сохраняет личные статусы not_started/in_progress/ready/done. «Сдано» явно является личной отметкой, не подтверждением преподавателя. Опубликованные задания доступны только участникам; общий прогресс других студентов не раскрывается.
- Страница предмета: преподаватель, требования к зачёту, ссылки HTTPS, занятия и работы. Изменять общие данные могут существующие управляющие роли.
- Подгруппа по умолчанию берётся из аккаунта, сохранённые фильтры изолированы по аккаунту; предусмотрены гостевые фильтры. День/неделя/месяц, компактные карточки, сворачивание прошедших/пустых дней и нижняя мобильная навигация с «Ещё».
- Уведомления: конкретные новые/перенесённые/отменённые пары, объединение массовых правок; фильтрация аудитории и тихие часы; уведомления о работах и сроках. Telegram подключается одноразовой ограниченной по времени ссылкой из авторизованного аккаунта; только приватный чат, возможность отключения и проверки. Очереди и категория queue удаляются. Никаких реальных рассылок при разработке.
- Web Push: показывать срок действия устройства/необходимость переподключения после окончания сеанса. Telegram не привязан к сроку браузерного сеанса, но учитывает активность аккаунта и доступ к аудитории.
- Автоматические внешние копии: запуск по systemd timer, закрытые права, проверка архива, доставка через заранее настроенный SSH/SCP без паролей в аргументах, тест восстановления; локальные копии сохраняются при ошибке выгрузки. Скрипт не активирует таймер и не подключается к чужому серверу сам.
- Оптимизация: исключить сервис/БД очереди из новой конфигурации (3 API), переиспользовать внутренние HTTP-соединения, не загружать все сообщения для счётчика/пагинации, lazy-load тяжёлых разделов, опрос только видимых страниц. Не добавлять инфраструктуру Redis/Celery для одной группы.

## Совместимость и проверки
Существующие аккаунты, MFA, приглашения, расписание, исключения и уведомления сохраняются. Новые миграции только расширяют активные БД и удаляют устаревшие queue_enabled из расписания. Старые данные отдельной БД очереди не уничтожаются автоматически; перед обновлением сохранить предыдущую копию. Новые копии содержат auth/schedule/notifications. Внешние зависимости опциональны: отсутствие Telegram/SSH не мешает запуску.

Проверки: Python HTTP/permissions/migrations/concurrency, Telegram HTTP transport stub с 429/403/restart, frontend unit/build, browser flows на мобильном и desktop, отсутствие рабочих маршрутов queues, существующие MFA/calendar/offline scenarios. PR описывает реальные результаты и ограничения проверки Docker/production.
