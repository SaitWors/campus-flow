# Личные привычки и Telegram Mini App

Цель: один бот для владельца и приглашённых близких; у каждого личные
привычки, расписание, прогресс и магазин. Текущий Java-план владельца сохраняется.
Допущение: девушке нужен выбор своих занятий, а не обязательный курс Java.

## Данные и доступ

Существующий `/data/state.sqlite3` остаётся базой владельца. Реестр приглашений
и участников хранится отдельно в `/data/members.sqlite3`; базы приглашённых —
`/data/users/<telegram_id>/state.sqlite3`. Проверенный числовой Telegram ID
выбирает профиль; тело запроса никогда не выбирает чужой профиль. Только
владелец выдаёт одноразовые приглашения на 24 часа, максимум 10 участников.
Хранятся хеши приглашений, присоединение атомарно. Чужие цели/покупки недоступны.

SQLite v3 добавляет личные привычки с названием, описанием, длительностью,
временем и днями недели. Java и стандартное движение можно отключить.
Существующие награды и идемпотентность начислений сохраняются. Новые профили
начинают с движения и выключенного Java. Все операции и напоминания используют
один event loop и отдельные Service, без переключения глобального user_id.

## Mini App

Мобильные экраны: Сегодня (цели/таймер/перенос/выполнение), Прогресс (7 дней,
XP, серия, достижения), Награды (создание/удаление/подтверждение покупки),
Настройки (привычки, дни недели, расписание, часовой пояс, Java, пауза).
По уточнению пользователя: чёрный фон, тёмные карточки и мандариновые оранжевые
кнопки/акценты во всех экранах, независимо от темы Telegram. SVG, safe-area,
reduced-motion.
Демонстрационный режим не имеет доступа к реальным данным.

Сервер проверяет HMAC Telegram initData, срок 1 час, будущие auth_date,
повторы ключей и membership. Токен не попадает в браузер/URL/логи. JSON API
отдаёт только профиль авторизованного пользователя, вход из обычного браузера
не открывает данные. Изменения требуют POST JSON и валидной подписи.

## Подключение Campus Flow

Статические проверенные файлы Mini App входят в образ web Campus Flow.
Nginx маршрутизирует только ограниченные JSON endpoints `/habits/<UUID>/api/`
к `cfbot-<UUID>:8081` через отдельную сеть `campus-flow-habits`. HTML из образов
ботов не проксируется. Cookies Campus Flow в контейнер бота не передаются.
Нет Docker socket, host ports или новых привилегий. Образ бота опционально
заявляет `com.campus-flow.bot.miniapp=habits-v1`; старые образы работают как раньше.
Runner получает HTTPS origin из control plane и задаёт BOT_APP_URL. Кнопка
OPEN APP в меню чата задаётся через Bot API; профильная Main Mini App — через
BotFather вручную. Без URL чатовые команды продолжают работать.

## Приёмка

Миграция v2 сохраняет владельца, баланс, цели и Java. Два пользователя с
одинаковыми ID целей не могут воздействовать друг на друга. Приглашение нельзя
переиспользовать, просрочить или выдать гостю. Поддельный/старый initData
отклоняется. Закрытая цель не награждается дважды из чата и Mini App.
Личные привычки соблюдают дни недели, время, паузу и тихие часы.
Проверяются 360 px и desktop, клавиатура, пустые/ошибочные состояния.
Публикация GHCR — только main, production и BotFather в этой сессии не меняются.
