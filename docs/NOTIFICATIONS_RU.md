# Уведомления Campus Flow

В PR2 добавлен четвёртый сервис — notifications с отдельной PostgreSQL. Он отвечает за личную историю, Web Push, настройки и важные объявления. Сервисы не читают чужие базы.

## Что видит студент

- Колокольчик в верхней панели показывает реальное число непрочитанных сообщений, до «99+». Анимация счётчика адаптирована из предоставленных TutReact.js и TutCSS.css; SVG BellRing — Lucide, ISC.
- В истории есть все сообщения, фильтр непрочитанных, отдельное прочтение и «Прочитать все». Отметки хранятся на сервере и синхронизируются между устройствами.
- Изменения расписания объединяются в сообщение о необходимости проверить пары. Изменение шаблона на весь семестр не порождает отдельный push для каждой пары: события обрабатываются пакетами до 200.
- Вызов в очереди получает только вызванный студент. Перед отправкой повторно проверяются очередь, статус вызова, актуальность пары и её окончание.
- Объявления могут предназначаться всей группе, подгруппе или руководящим ролям.
- Важное объявление появляется поверх сайта до нажатия «Понятно», прочтения или истечения срока. Оно не мешает работе с открытой формой, не закрывается само через несколько секунд.
- Обычные сообщения расписания сохраняются до 30 дней, объявления — до установленного срока, вызов — до 10 минут или конца пары. История публикаций и журнал объявлений хранятся до 90 дней.

## Как включить push

Открыть «Настройки» → «Настройки уведомлений» → «Включить на этом устройстве» и разрешить уведомления в системном окне. Сайт предлагает настроить push, но не вызывает системный запрос без нажатия. После «Позже» предложение скрывается на неделю; настройки всегда доступны.

В браузере нужны HTTPS, Service Worker, Push API и Notifications API. Исключение для разработки — localhost. Работают современные Chrome, Firefox, Edge и Safari с поддержкой этих API. Встроенные браузеры мессенджеров могут не поддерживать подписку.

**iPhone/iPad:** iOS/iPadOS 16.4+, «Поделиться» → «На экран Домой» → запустить с этой иконки → включить уведомления. Обычная вкладка Safari на iPhone не заменяет установленное веб-приложение. Apple требует непосредственное действие пользователя для запроса разрешения.

**Android:** разрешить уведомления в браузере; для отдельного окна и иконки выбрать в меню браузера «Установить приложение» / «Добавить на главный экран».

Это адаптивное PWA, а не APK или приложение из App Store. Закрытая вкладка не мешает Web Push. Доставка зависит от сети, настроек ОС, энергосбережения и работы push-службы браузера; сайт не обещает доставку при выключенном устройстве или принудительно остановленном браузере.

## Настройки

- Категории push: расписание, вызов в очереди, объявления, личные вопросы.
- Всплывающие важные объявления на самом сайте — отдельный переключатель.
- Тихие часы с выбранным часовым поясом. Они действуют на все push, включая важные; переполнение через полночь поддерживается. Начало и конец должны различаться.
- Просроченный вызов не отправляется после тихих часов. Другие сообщения могут быть отправлены после них, пока не истекли.
- Язык push RU/EN задаётся отдельно от языка интерфейса.
- Текст на экране блокировки по умолчанию скрыт. Его можно включить осознанно.
- До пяти устройств на аккаунт. Можно отключить текущее или любое другое своё устройство.
- Пробное уведомление также следует категориям и тихим часам. Нажатие ограничено одним новым сообщением в минуту.
- Выход из аккаунта, блокировка, сброс/смена пароля и окончание семидневной сессии останавливают следующие отправки на связанную подписку. После нового входа ранее подключённое устройство перепривязывается к новой сессии; при необходимости нажать кнопку подключения снова.

Уже переданный в push-службу пакет отозвать нельзя. Поэтому отправитель проверяет состояние перед передачей, а Service Worker не показывает подробности сообщения, если сохранённый владелец устройства не совпадает. Старые подписки удаляются при ответах 404/410 и по сроку хранения.

## Работа старосты, заместителя и администратора

«Управление» → «Объявления»:

1. Ввести заголовок и текст. Это обычный текст; HTML и скрипты не исполняются.
2. При желании заполнить английский вариант. Без него английский интерфейс покажет русский оригинал. Объявления не отправляются в сторонний переводчик.
3. Выбрать аудиторию, срок 1–168 часов и флаг важности.
4. Проверить предпросмотр и нажать «Опубликовать объявление».
5. При необходимости отозвать публикацию. Она исчезнет с сайта, а ещё не отправленные задачи push удалятся.

Одинаковый повтор публикации с тем же ключом не создаёт дубликаты. Лимит — пять публикаций за десять минут на одного руководителя. Получатели фиксируются из активных участников на момент публикации; будущие регистрации не получают старую рассылку. Потерявший руководящую роль пользователь больше не видит объявления для руководителей. В журнале видны автор, публикация и отзыв.

## Надёжность и безопасность

- Событие вызова записывается в одной транзакции с вызовом. События расписания уже сохранялись так же.
- Курсоры чтения, личные сообщения и задания push сохраняются транзакционно в БД уведомлений. При сбое до commit они откатываются вместе.
- При первом подключении сервиса старые события пропускаются. При последующих рестартах обработка продолжается с сохранённого курсора. Изменения расписания старше часа не вызывают запоздалую рассылку.
- Повторная доставка после аварии возможна; стабильный tag заменяет уведомление на устройстве. Для HTTP 429 и 5xx — до пяти попыток с увеличением задержки.
- VAPID-ключ генерируется внутри сервиса при первом запуске и сохраняется в его закрытой БД. В браузер передаётся только публичный ключ. Не нужны облачный аккаунт или платная подписка на рассылки.
- Перед каждой отправкой auth проверяет хеш связанной сессии, пользователя и его текущий статус. Сырой токен сессии в notifications не хранится.
- Запись, прочтение, настройки, подписки и публикации проверяют текущую сессию и CSRF. Подписками и входящими сообщениями нельзя управлять от имени другого пользователя.
- Capability URL подписок, приватный VAPID-ключ и криптографические ключи не возвращаются списком устройств и не пишутся в логи.
- URL доставки допускаются только для известных адресов Google, Mozilla, Apple и Microsoft. HTTPS, публичные DNS-адреса, проверка сертификата, отсутствие переходов по редиректам и отключённые proxy-переменные защищают от превращения подписки в произвольный запрос с сервера.
- Браузерный Service Worker не кеширует приватное расписание, HTML авторизованного приложения или API. При отсутствии сети показывает простую страницу ошибки; очереди требуют актуальных данных.
- Все четыре базы и конфигурацию нужно резервировать вместе. Бэкапы содержат персональные данные и ключи — хранить их закрыто.

## API

| Метод | Путь | Доступ |
|---|---|---|
| GET | /api/notifications/config | Активный участник |
| GET / PUT | /api/notifications/preferences | Собственные настройки |
| GET | /api/notifications/inbox?offset=0&unread_only=false | Собственная история |
| POST | /api/notifications/read | Собственные сообщения; ids или before |
| GET / POST | /api/notifications/subscriptions | Собственные устройства |
| DELETE | /api/notifications/subscriptions/{id} | Собственное устройство |
| POST | /api/notifications/test | Собственный пробный push |
| GET / POST | /api/notifications/announcements | Староста, заместитель, администратор |
| DELETE | /api/notifications/announcements/{id} | Староста, заместитель, администратор |
| GET | /api/notifications/audit | Староста, заместитель, администратор |

OpenAPI: /api/notifications/openapi.json. Внешний Nginx не публикует /internal/*; ключ внутреннего API из внешних запросов удаляется.

## Гости и личные вопросы

Гости просматривают только публичное расписание. Подтверждённые участники могут вести личную переписку с выбранным сотрудником; категория push «Личные вопросы» настраивается отдельно. Содержание вопросов не попадает в push. [Правила доступа, роли и сценарии](GUEST_QUESTIONS_ROLES_RU.md).
