# Учебный день, работы и предметы

После входа открывается **Сегодня**: текущая или ближайшая пара с отсчётом времени, занятия на день, ближайшие сроки и личные работы. В расписании доступны день, неделя и месяц. Подгруппа по умолчанию берётся из аккаунта; выбранные фильтры, компактные карточки и сворачивание дней сохраняются для этого аккаунта на устройстве. У студента список работ ограничен общей и своей подгруппой.

## Работы

Староста, заместитель и администратор добавляют работу: предмет, название, описание, подгруппу, срок и HTTPS-ссылку на материалы. Срок вводится в часовом поясе семестра и хранится как UTC. Работа может не иметь срока. Удаление архивирует её.

Каждый участник отмечает собственный статус: **Не начато → В работе → Готово → Сдано**. Эти отметки не видны одногруппникам и руководителям. Статус «Сдано» исключает работу из напоминаний этому участнику. Перенос работы в другую подгруппу сразу прекращает доступ прежней подгруппы.

Одновременные изменения проверяют ревизию записи. При конфликте обновите данные и повторите нужную правку: система не перезаписывает чужое изменение молча.

## Предметы

Страница предмета собирает ближайшие занятия, работы, преподавателя, требования и ссылки на материалы. Сведения доступны вошедшим участникам. Редактирование — руководителям группы. Каталог предметов автоматически пополняется из названий занятий; импорт расписания не добавлен.

## Уведомления

Изменения расписания показывают предмет, дату и изменившиеся время, аудиторию или статус. Изменения нескольких занятий объединяются. Категория «Работы» включает создание, изменение, архивирование и напоминания о сроке. Настройки языка, подгруппы, категорий, подробностей и тихих часов применяются к внешним каналам. Подключение и ограничения описаны в [инструкции уведомлений](NOTIFICATIONS_RU.md).

## Обновление существующей установки

Сначала сделайте полную резервную копию. Текущие схемы: **auth 3, schedule 5, notifications 3**. Миграции сохраняют занятия, переводы, личную переписку и сеансы, добавляют таблицы работ и материалов и убирают старое поле занятия. Обычный откат на прежний образ несовместим с новыми схемами; нужна подходящая копия и прежний код. [Материалы предметов: права, файлы и восстановление](MATERIALS_RU.md).

Система записи на сдачу полностью удалена из интерфейса, API и фоновой обработки. Запуск с `--remove-orphans` убирает её оставшиеся контейнеры, сохраняя тома. Исторические данные в старых томах и резервных копиях автоматически не стираются. Новые копии содержат три рабочие базы и архив материалов; старые production-копии с четвёртой базой проверяются целиком, а восстанавливаются только три действующие базы.

## Автоматическая внешняя копия

`scripts/external_backup.py` использует согласованный production-бэкап, проверяет контрольные суммы и создаёт приватный `.tar.gz`. Затем отправляет его через SSH, проверяет SHA-256 на удалённой стороне и только после совпадения публикует файл. Ошибка передачи сохраняет полную локальную копию. Старые копии автоматически не удаляются.

1. Настройте отдельный SSH-аккаунт хранилища, ключ и проверенную запись `known_hosts` для пользователя службы. Передача использует `BatchMode=yes` и `StrictHostKeyChecking=yes`.
2. Проверьте пути `/opt/campus-flow` в `infra/systemd/campus-flow-backup.service`; при другом каталоге исправьте `WorkingDirectory` и `ExecStart`.
3. Создайте `/etc/campus-flow-backup.env` из `infra/systemd/backup.env.example`, заполните хост и каталог, задайте права `600`.
4. Сначала выполните вручную:

```bash
python3 scripts/external_backup.py --host backup@example.org --remote-directory /srv/backups/campus-flow
```

5. Установите примеры службы и таймера:

```bash
sudo install -m 644 infra/systemd/campus-flow-backup.service /etc/systemd/system/
sudo install -m 644 infra/systemd/campus-flow-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now campus-flow-backup.timer
systemctl list-timers campus-flow-backup.timer
journalctl -u campus-flow-backup.service
```

Таймер запускает копирование ежедневно около 04:00 по времени сервера и догоняет пропущенный запуск. На время согласованного дампа сайт кратковременно останавливается. Архив содержит персональные данные и ключи конфигурации: храните его в закрытом хранилище с шифрованием диска и отдельно проверьте восстановление по [production-инструкции](DEPLOY_TIMEWEB40_RU.md). Сама передача зашифрована SSH; архив отдельным ключом не шифруется.
