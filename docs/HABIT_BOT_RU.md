# Подключение напоминалки Patchboard через панель

Текущая версия поддерживает личные профили, приглашения и OPEN APP.
Для обновления работающего бота сначала прочитай
[инструкцию Mini App](HABIT_MINIAPP_RU.md): нужны новые web/API и Runner.

Инструкция именно для формы «Подключить бота». ZIP в поле образа не подходит:
нужен публичный GHCR-образ с настоящим digest, который сформирует GitHub Actions.

## 1. Дождаться сборки после merge

После слияния изменений в main открой SaitWors/campus-flow → Actions →
**Patchboard reminder bot**. Дождись зелёного verify, затем publish.
В Summary скопируй полную строку с digest:

```text
ghcr.io/saitwors/campus-flow-habit-bot@sha256:<64 настоящих hex-символа>
```

Тег main/latest, SHA коммита или выдуманный digest не подходят. В PR workflow
проверяет образ; публикация с packages:write идёт только из main. Настоящего
Telegram-токена в GitHub нет. Новый репозиторий не требуется.

При первой публикации проверь GitHub → профиль → Packages →
campus-flow-habit-bot → Package settings → видимость **Public**. Даже у
публичного репозитория пакет может первоначально быть private.

## 2. Обновить Runner на VPS

На сервере с уже установленным Runner и чистым checkout:

```bash
cd /opt/campus-flow
git status --short
git pull --ff-only origin main
bash scripts/install_bot_runner.sh start
systemctl status campus-flow-bot-runner --no-pager
```

Если status показывает свои правки, сначала сохрани и разбери их: не используй
reset/clean вслепую. start перечитывает новый Python-код Runner, не меняет ключи
и не удаляет данные Campus Flow. Новая миграция его БД не нужна. Текст подписи
в интерфейсе обновится при обычном production deploy сайта.

Если Runner ещё не установлен, сначала пройди prepare → штатный deploy API →
start по [основной инструкции](BOT_MANAGER_RU.md).

## 3. Заполнить форму со скриншота

| Поле | Значение |
| --- | --- |
| Платформа | Telegram |
| Название бота | Patchboard — Java и спорт |
| Образ приложения | Полная строка image@sha256 из Actions Summary |
| Токен из BotFather | Токен нового личного бота |

Нажми «Подключить бота», затем «Запустить». Дождись загрузки образа и
синхронизации Runner, открой логи. Не используй токен уведомлений Campus Flow.
Останови другие копии этого же токена на Windows/в отдельном Compose.

## 4. Активировать себя владельцем

На VPS из обновлённого репозитория:

```bash
cd /opt/campus-flow
python3 bots/mandarin-habits/habitbot/activation.py
```

Введи токен при скрытом запросе. Скрипт не делает сетевых запросов и не сохраняет
токен; выводит отдельную команду `/claim КОД`. Отправь её личным сообщением
**своему боту**. Не отправляй в чат сам токен и не передавай код другим людям.
Первый посетитель с /start владельцем не становится. Код основан на HMAC;
после активации повторное назначение владельца закрыто.

## 5. Продолжить Java-план

Если первое занятие уже сделал и залил в SaitWors/Patchboard, до первого
зачёта в боте отправь:

```text
/course start 2
/time code 20:00
/time sport 10:00
/tz Europe/Moscow
/today
```

За первый день вне бота монеты не начисляются. Календарь не перескакивает
через незавершённые темы. /lesson присылает исходную заметку, /course показывает
прогресс. Следующее занятие выдаётся со следующего дня после выполнения текущего.
Критерии проверяешь сам, затем нажимаешь «Готово»; автоматической проверки Git нет.

## 6. Проверить сохранение

Выполни цель, открой /profile и /course. Нажми «Перезапустить» в панели,
подожди запуска и повтори команды: владелец, баланс и занятие должны сохраниться.
Получи /backup. Для обновления меняй digest **той же карточки**: новая карточка
создаёт новый UUID и отдельное пустое хранилище.

## Если не работает

- Ошибка /data или read-only database: Runner старый или не перечитал код.
- Образ не скачивается: проверь digest и публичную видимость GHCR.
- Conflict: токен одновременно работает в двух местах.
- «Бот ещё не активирован»: выполни activation.py и отправь /claim КОД.
- Нет напоминаний: проверь /start, время, часовой пояс, /pause и тихие часы 23–08.

```bash
journalctl -u campus-flow-bot-runner --since '10 minutes ago' --no-pager
```

Том cfbot-data-<UUID> сохраняется даже после удаления карточки. Удаление такого
тома выполняется отдельно после копии и проверки UUID. Общий volume prune не нужен.
Копии БД Campus Flow этот том автоматически не включают: используй /backup.


## Восстановление из backup

1. Скачай SQLite-файл, полученный от /backup, и загрузи его на VPS как
   `/opt/campus-flow/backups/habit-restore.sqlite3`. Сохрани права 0600: stdin
   передаст содержимое контейнеру UID10001, менять владельца файла не нужно.
2. В панели открой нужную карточку → Конфигурация и скопируй **ID бота** и
   строку **Образ**. Останови бота кнопкой «Остановить» и дождись отчёта Runner.
   Сам Runner не останавливай: он должен получить желаемое состояние stopped.
3. При восстановлении в новую карточку сначала один раз запусти её, дождись
   создания тома, затем останови. Это новый UUID, старый том не удаляется.

В SSH подставь реальные ID/образ из карточки, а не подписи ниже:

```bash
cd /opt/campus-flow
CF_BOT_ID=UUID_ИЗ_КАРТОЧКИ
CF_BOT_IMAGE=ОБРАЗ_С_DIGEST_ИЗ_КАРТОЧКИ
CF_BOT_VOLUME="cfbot-data-$CF_BOT_ID"
docker volume inspect "$CF_BOT_VOLUME" >/dev/null
test -z "$(docker ps -q --filter "label=campus-flow.bot-id=$CF_BOT_ID")" || { echo 'Бот ещё работает: останови его через панель'; exit 1; }
```

Если в этом томе уже есть прогресс, сначала сделай его согласованную копию:

```bash
umask 077
mkdir -p backups
docker run --rm --read-only --network none --user 10001:10001 \
  --mount "type=volume,source=$CF_BOT_VOLUME,target=/data" \
  --env BOT_DATA_DIR=/data "$CF_BOT_IMAGE" python -m habitbot.backup \
  > "backups/habit-before-restore-$(date +%F-%H%M%S).sqlite3"
```

Восстанови скачанную копию через stdin. Вместо `ТВОЙ_TELEGRAM_ID` поставь
положительное число — владельца исходной копии (это твой личный /id).
Ни настоящий, ни фиктивный Telegram-токен для этого helper не требуется.

```bash
docker run --rm -i --read-only --network none --user 10001:10001 \
  --tmpfs /tmp:rw,nosuid,nodev,size=32m \
  --mount "type=volume,source=$CF_BOT_VOLUME,target=/data" \
  --env BOT_DATA_DIR=/data "$CF_BOT_IMAGE" \
  python -m habitbot.restore --owner-id ТВОЙ_TELEGRAM_ID - \
  < backups/habit-restore.sqlite3
```

Проверяются целостность, версия, ожидаемый владелец и блокировка работающего
процесса. Команда заменяет состояние именно выбранного тома на копию.
После успешного завершения нажми «Запустить» в той же карточке. Проверь
/profile и /course: владелец и прогресс уже восстановлены, повторный /claim
не нужен. Перед заменой образа или удалением старого тома сохрани резервную копию.
