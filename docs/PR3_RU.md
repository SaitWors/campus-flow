# PR3 — предметы, время пар, предпросмотр и защита аккаунта

Изменения собраны от `main` после PR2. Сохранённого кода зависшего PR3 не было ни в опубликованных ветках, ни в доступных рабочих копиях. Функции восстановлены по приложенным скриншотам. Размещение на сервере и изменение домена в этот PR не входят.

## Как пользоваться

### Предметы и время

1. Откройте **Управление → Предметы и время пар**.
2. В справочнике уже будут названия из существующих шаблонов и отдельных занятий. Демонстрационные предметы не добавляются. Список общий для администратора, старосты и заместителя.
3. При добавлении пары выберите **Ранее введённый предмет**: подставятся название и сохранённый ручной перевод. Автоперевод работает через прежний сервис; он не требуется для сохранения предмета.
4. Новый предмет можно ввести вручную. Он попадёт в справочник после успешного сохранения пары. Отличия регистра и лишние пробелы не создают дубли.
5. Если менять русское название вручную, поле ручного английского перевода очищается, чтобы не оставить перевод другого предмета. Названия и переводы существующих пар автоматически не заменяются.

Начальные интервалы взяты с предоставленной картинки:

| Пара | Начало | Конец |
| --- | --- | --- |
| I | 09:30 | 11:00 |
| II | 11:15 | 12:45 |
| III | 13:00 | 14:30 |
| IV | 15:10 | 16:40 |
| V | 16:55 | 18:25 |

Интервалы можно менять, добавлять и удалять; допускается от 1 до 12 непересекающихся интервалов. Выбор интервала в форме заполняет время, но оба поля остаются редактируемыми. Изменение списка интервалов **не переписывает расписание**, даты семестра или очереди. Пресеты имеют собственную ревизию для защиты от одновременных сохранений.

### Изменение шаблона

**Управление → Шаблоны пар → Изменить → Посмотреть изменения.**

Появляется перечень затронутых дат с изменяемыми полями. Сохранение выполняется второй кнопкой **Применить изменения**. Отдельные исключения и занятия за прошлые даты остаются прежними. Если после предпросмотра другой руководитель изменил расписание, сервер отклонит сохранение и попросит повторить предпросмотр. Любое изменение полей формы также сбрасывает предпросмотр.

Предпросмотр запускает тот же расчёт, что и сохранение, внутри откатываемой транзакции. Он не публикует события и не отправляет уведомления. Для клиентов API обновление шаблона теперь требует `preview_token`, полученного от `POST /api/schedule/rules/{id}/preview` для того же тела запроса.

### Второй фактор и сеансы

**Настройки → Двухфакторная аутентификация → Настроить второй фактор.**

1. Введите текущий пароль.
2. Добавьте показанный ключ вручную в приложение-аутентификатор: TOTP, SHA-1, 6 цифр, 30 секунд. На поддерживаемом устройстве можно использовать ссылку открытия приложения.
3. Введите код приложения и включите защиту. Другие сеансы завершатся.
4. Сохраните десять резервных кодов. Полный список показывается один раз; каждый код одноразовый.

Вход состоит из пароля и отдельного подтверждения. Пока код не проверен, новый сеанс не выдаётся. Проверка входа живёт пять минут и допускает пять неудачных попыток. Один и тот же TOTP нельзя повторно использовать; после включения дождитесь следующего кода, прежде чем входить заново. Отключение защиты и замена резервных кодов требуют пароля и действующего кода. Новый набор отменяет старый и завершает остальные сеансы.

**Настройки → Активные сеансы** показывает устройство, время входа и текущий сеанс. Можно завершить одно из других устройств или все остальные. Название устройства определяется по строке браузера и не является подтверждением его подлинности.

Смена пароля при включённом втором факторе также требует кода. Сброс пароля через старосту **не отключает второй фактор**. При потере приложения нужен резервный код; веб-интерфейс обхода второго фактора не добавлен.

### Подписка и офлайн-копия

В **Настройки → Подписка на календарь** выберите подгруппу, скопируйте ссылку и добавьте её в календарное приложение как календарь по URL. Язык ссылки соответствует языку интерфейса. Ссылка стабильна и не требует сеанса Campus Flow. В ней только публичные сведения о занятиях. Отменённые и убранные из шаблона занятия сохраняются в потоке со статусом отмены, чтобы внешний календарь мог их убрать. Частоту обновления выбирает календарное приложение; мгновенное обновление не гарантируется.

В **Настройки → Расписание без интернета** нажмите **Сохранить офлайн-копию**. На этом устройстве сохранится публичное расписание на ближайшие 28 дней для выбранной выше подгруппы. Офлайн-страница показывает время сохранения и предупреждение об устаревании. Копию можно открыть и удалить; она не обновляется автоматически.

В офлайн-копию и подписку не попадают преподаватели, заметки, ссылки на встречи, переписка, списки участников и очереди. Service Worker хранит только отдельную офлайн-страницу, её статические файлы и явно сохранённый публичный снимок. HTML основного приложения и приватные API не кешируются. Нужен HTTPS; для локальной разработки подходит localhost. В приватном режиме или при очистке браузера копия может исчезнуть.

### Анимации

Добавлены короткие переходы между разделами, появление диалога и небольшой отклик карточек. При отсутствии View Transitions приложение переключается обычным способом. Учитываются системное уменьшение движения и настройка **Уменьшить анимации**; выбор сохраняется на устройстве.

## Обновление существующей установки

Перед обновлением сделайте штатную копию четырёх баз и сохраните используемый `.env`. После слияния PR применяйте обычную процедуру обновления из [инструкции сервера](DEPLOY_FRIEND_RU.md). Не используйте `down --volumes` для обновления.

| База | Версия схемы после PR3 |
| --- | --- |
| auth | 3 |
| schedule | 3 |
| queue | 2 |
| notifications | 2 |

Миграции сохраняют пользователей, хеши паролей, действующие сеансы, расписание, исключения и прежнее время занятий. Старым сеансам присваиваются отдельные публичные идентификаторы; время в списке для таких сеансов — момент обновления. Новые таблицы сохраняются штатными скриптами полного резервного копирования.

Ключи TOTP зашифрованы Fernet; ключ шифрования выводится из `INTERNAL_TOKEN` с отдельным назначением. **Сохраняйте прежний `INTERNAL_TOKEN` вместе с резервной копией.** Его произвольная замена сделает ключи аутентификаторов нечитаемыми. Резервные коды и временные подтверждения входа хранятся хешами. Секреты и коды не пишутся в журнал действий.

Для отката к PR2 нужна соответствующая резервная копия баз схемы 2; старый код не должен запускаться с новой схемой.
