# Автоперевод названий RU → EN

> PR2: переводчик включается отдельно через COMPOSE_PROFILES=translation и TRANSLATION_WORKER=true. Обычный запуск обходится без модели. Инструкция для сервера друга: [DEPLOY_FRIEND_RU.md](DEPLOY_FRIEND_RU.md).

При включённом профиле translation пустое поле «Название на английском» включает автоматический перевод. После паузы ввода форма показывает предпросмотр. Введите свой вариант для точного термина; очистите его, чтобы вернуть автоперевод.

Фоновый процесс переводит и уже существовавшие пары с пустым английским названием. Результаты сохраняются в schedule-db. Расписание подхватывает их при очередном обновлении; английская страница шаблонов повторяет загрузку, пока есть ожидающие перевода названия.

## Правила

- `title` — исходное русское название, `title_en` — сохранённый ручной вариант.
- Вычисляемые поля ответа `title_en_auto` и `translation_pending` не передаются в запросы изменения пары.
- В английском интерфейсе и ICS: ручной вариант → автоматический вариант → исходное название.
- Ручной текст не перезаписывается. Переименование берёт автоперевод по новому исходному тексту. Ручной перевод при переименовании нужно проверить самостоятельно.
- Перевод не меняет время, ревизии, ID и события занятий, поэтому не вызывает остановку очереди.
- При сбое можно сохранять и просматривать расписание; будет видно исходное название. Повтор не раньше чем через 60 секунд.
- ФИО, аудитории, заметки и задания в очередях не переводятся. Специальные сокращения иногда требуют ручного исправления.

## Установка

При COMPOSE_PROFILES=translation и TRANSLATION_WORKER=true команда `docker compose up --build -d --wait` включает **LibreTranslate v1.9.6**. Одна RU → EN модель скачивается и прогревается при сборке. В рабочем контейнере сеть translation_net имеет internal: true; в ней только schedule и translator, порт 5000 не опубликован. Файловая система только для чтения, временные каталоги, снятые capabilities, ограничения CPU/RAM.

Использованы [официальный релиз](https://github.com/LibreTranslate/LibreTranslate/releases/tag/v1.9.6), [Dockerfile](https://github.com/LibreTranslate/LibreTranslate/blob/v1.9.6/docker/Dockerfile), [установщик моделей](https://github.com/LibreTranslate/LibreTranslate/blob/v1.9.6/scripts/install_models.py), [документация](https://docs.libretranslate.com/guides/installation/). Платные ключи не нужны.

Базовый образ зафиксирован по digest, RU → EN модель — по версии, URL и SHA256. Сохраняйте собранный образ для воспроизводимого развёртывания: исходный образ содержит зафиксированные зависимости. Во время обычного запуска модели заново не скачиваются.

Клиент отправляет только q, source=ru, target=en, format=text на фиксированный внутренний адрес. Не передаёт cookie, внутренний токен или CSRF. Ответ максимум 4 КиБ, результат до 120 символов; текст выводится через React, без HTML-вставки. Предпросмотр допускает только admin/head/deputy, защищён CSRF и лимитом 20 запросов/мин на аккаунт в одном процессе. Compose запускает один процесс schedule.

## Обновление

Сначала сделайте копию scripts/backup.sh или scripts/backup.ps1 и сохраните её вне VM. При старте миграция schedule-db **1 → 2** добавит title_translations. Ручные названия, занятия, пользователи и очереди сохраняются. В PR2 также обновляются auth, queue и notifications; см. [миграции PR2](GUEST_QUESTIONS_ROLES_RU.md).

Старая версия откажется работать с новой схемой. Для отката нужны предыдущий образ и соответствующая копия базы — [восстановление](OPERATIONS_RU.md). Не удаляйте volumes ради обновления.

В режиме разработки без Docker отдельный переводчик не запускается; доступны исходные названия и ручные переводы. TRANSLATION_WORKER=false отключает фоновый перевод для тестов. Для полного автоперевода используйте Compose.

## Проверки

Unit/HTTP: миграция существующей базы, кеш, ручной приоритет, переименование, отсутствие изменений ревизий/событий, ошибки/повторы, роли/CSRF, лимиты, фиксированный адрес и некорректные ответы. GitHub Actions: настоящая RU → EN модель во внутренней сети, PostgreSQL, Nginx, браузер и backup/restore. Результат конкретного запуска — в проверках PR.

## Исправление IncompleteRead в PR2

Вместо install_models.py --load_only_lang_codes en,ru установлен ровно один пакет RU → EN 1.9. Направление EN → RU не загружается.

- URL из официального Argos package index: https://argos-net.com/v1/translate-ru_en-1_9.argosmodel
- SHA256: e9ba8bf722d10a4a4c39f74289d5938fd47eac08dbe4ed0afd22d89445a5c3ac
- Установщик: scripts/install_ru_en_model.py — фиксированная версия, проверка хеша и ZIP, resume, пять попыток, кеш BuildKit.
- При изменении файла на сервере моделей сборка завершится ошибкой проверки; хеш нельзя отключать для обхода ошибки.
- У LibreTranslate v1.9.6 исправлена проверка «не меньше двух моделей»: для одного направления достаточно одного установленного пакета. Это предотвращает попытку автоматически скачать обратное направление при старте.
- После установки выполняется настоящий перевод. Работающий контейнер остаётся в изолированной сети.
- Доступность внешнего сервера моделей всё равно нужна для первого скачивания. Без профиля translation приложение собирается без него.

[Официальный индекс Argos](https://github.com/argosopentech/argospm-index/blob/main/index.json), [Argos Translate](https://github.com/argosopentech/argos-translate).

### Дополнительная загрузка MiniSBD

В проверке сборки обнаружена отдельная загрузка ONNX-модели разбиения предложений, которая могла завершаться HTTP 504. Для названий до 120 символов разбиение не требуется. scripts/configure_title_translator.py реализует локальный вариант ChunkType.NONE в зафиксированном Argos 1.11: название переводится одним сегментом, без скачивания MiniSBD. Замены проверяют ожидаемый исходный код и останавливают сборку при несовместимом обновлении upstream. Это дополнение не превращает сервис в переводчик больших документов; лимит 120 символов сохраняется. [Код Argos](https://github.com/argosopentech/argos-translate/blob/v1.11.0/argostranslate/translate.py).
