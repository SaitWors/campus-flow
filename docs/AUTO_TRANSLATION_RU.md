# Автоперевод названий RU → EN

Пустое поле «Название на английском» включает автоматический перевод. После паузы ввода форма показывает предпросмотр. Введите свой вариант для точного термина; очистите его, чтобы вернуть автоперевод.

Фоновый процесс переводит и уже существовавшие пары с пустым английским названием. Результаты сохраняются в schedule-db. Расписание подхватывает их при очередном обновлении; английская страница шаблонов повторяет загрузку, пока есть ожидающие перевода названия.

## Правила

- `title` — исходное русское название, `title_en` — сохранённый ручной вариант.
- Вычисляемые поля ответа `title_en_auto` и `translation_pending` не передаются в запросы изменения пары.
- В английском интерфейсе и ICS: ручной вариант → автоматический вариант → исходное название.
- Ручной текст не перезаписывается. Переименование берёт автоперевод по новому исходному тексту. Ручной перевод при переименовании нужно проверить самостоятельно.
- Перевод не меняет время, ревизии, ID и события занятий, поэтому не вызывает остановку очереди.
- При сбое можно сохранять и просматривать расписание; будет видно исходное название. Повтор не раньше чем через 60 секунд.
- ФИО, аудитории, заметки и задания в очередях не переводятся. Специальные сокращения иногда требуют ручного исправления.

## Установка

`docker compose up --build -d --wait` включает **LibreTranslate v1.9.6**. RU/EN-модели скачиваются и прогреваются при сборке. В рабочем контейнере сеть translation_net имеет internal: true; в ней только schedule и translator, порт 5000 не опубликован. Файловая система только для чтения, временные каталоги, снятые capabilities, ограничения CPU/RAM.

Использованы [официальный релиз](https://github.com/LibreTranslate/LibreTranslate/releases/tag/v1.9.6), [Dockerfile](https://github.com/LibreTranslate/LibreTranslate/blob/v1.9.6/docker/Dockerfile), [установщик моделей](https://github.com/LibreTranslate/LibreTranslate/blob/v1.9.6/scripts/install_models.py), [документация](https://docs.libretranslate.com/guides/installation/). Платные ключи не нужны.

Тег образа зафиксирован, модели выбирает официальный индекс во время build. Это не криптографическая фиксация всего содержимого: сохраняйте собранный образ для воспроизводимого развёртывания и повторяйте проверку модели после пересборки. Во время обычного запуска модели заново не скачиваются.

Клиент отправляет только q, source=ru, target=en, format=text на фиксированный внутренний адрес. Не передаёт cookie, внутренний токен или CSRF. Ответ максимум 4 КиБ, результат до 120 символов; текст выводится через React, без HTML-вставки. Предпросмотр допускает только admin/head/deputy, защищён CSRF и лимитом 20 запросов/мин на аккаунт в одном процессе. Compose запускает один процесс schedule.

## Обновление

Сначала сделайте копию scripts/backup.sh или scripts/backup.ps1 и сохраните её вне VM. При старте миграция schedule-db **1 → 2** добавит title_translations. Ручные названия, занятия, пользователи и очереди сохраняются. Схема остальных баз остаётся 1.

Старая версия откажется работать с новой схемой. Для отката нужны предыдущий образ и соответствующая копия базы — [восстановление](OPERATIONS_RU.md). Не удаляйте volumes ради обновления.

В режиме разработки без Docker отдельный переводчик не запускается; доступны исходные названия и ручные переводы. TRANSLATION_WORKER=false отключает фоновый перевод для тестов. Для полного автоперевода используйте Compose.

## Проверки

Unit/HTTP: миграция существующей базы, кеш, ручной приоритет, переименование, отсутствие изменений ревизий/событий, ошибки/повторы, роли/CSRF, лимиты, фиксированный адрес и некорректные ответы. GitHub Actions: настоящая RU/EN-модель во внутренней сети, PostgreSQL, Nginx, браузер и backup/restore. Результат конкретного запуска — в проверках PR.
