# Мандарин — личные привычки и Telegram Mini App

**Новая версия:** личные профили по приглашению и чёрно-оранжевая Mini App.
[Обновление, приглашения и OPEN APP](../../docs/HABIT_MINIAPP_RU.md).
Приглашённые выбирают свои занятия; Java не обязательна.

Telegram-бот для **Campus Flow → Управление → Боты**. Напоминает о движении
и первом незавершённом занятии из переданного Obsidian-плана Patchboard.
Все 30 исходных заметок входят в образ; календарные даты не переключают тему.

**Подключение:** [пошаговая инструкция для формы](../../docs/HABIT_BOT_RU.md).
Образ собирается workflow **Patchboard reminder bot** в этом же репозитории.
Новый репозиторий создавать не нужно.

## Курс и награды

- `/course` — прогресс 30 занятий; `/lesson` — цель, критерии и полная исходная .md-заметка.
- `/course start 2` — начать со второго занятия, если первое уже сделал вне бота.
  Доступно до первого зачёта курса; за предыдущие занятия монеты не начисляются.
- Пропуск оставляет тему прежней. Следующий урок приходит на следующий день
  после выполнения текущего. После дня 30 курс не начинается заново ради монет.
- За урок: 50 XP/30 монет, время строго из заметки. Движение: исходно
  20 минут, 30 XP/20 монет. За обе цели за день — ещё 20 XP/10 монет.
- `/difficulty` меняет только движение. Выполнение подтверждаешь сам кнопкой:
  бот не проверяет Git-коммиты и не читает локальный vault автоматически.
- Магазин своих наград, серия, достижения, таймер, пауза и `/backup` сохранены.

## Владелец и хранение

Образ не содержит твоего Telegram ID. Получи отдельный код активации локально:

```bash
python3 bots/mandarin-habits/habitbot/activation.py
```

Ввод токена скрыт. Своему боту отправь только выведенную команду `/claim КОД`.
Сам токен в чат не отправляй. Обычный первый `/start` не захватывает профиль.
Повторно переназначить владельца нельзя. Токен и код в базе не хранятся.

Образ заявляет `com.campus-flow.bot.storage=data-v1` и готовит `/data` для
UID 10001. Обновлённый Runner даёт отдельный именованный том по UUID карточки.
Перезапуск и смена digest той же карточки сохраняют владельца, монеты и урок.
На старом Runner запись в read-only /data завершится ошибкой: автоматического
перехода на /tmp с потерей данных нет. После удаления карточки том сохраняется.

## Разработка

Из этой папки, с Python 3.12:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

Для отдельного Compose сохрани .env.example как .env, задай BOT_TOKEN и
выполни `docker compose up --build -d`. Владелец активируется через /claim
либо задаётся числом OWNER_ID. Основной требуемый способ — панель Campus Flow.
SQLite v1 автоматически мигрирует в v2, старые монеты и магазин сохраняются.

Восстановление существующей или новой карточки: [точные команды](../../docs/HABIT_BOT_RU.md#восстановление-из-backup). Офлайн-helper не требует Telegram-токен; для пустого тома нужен явный ожидаемый --owner-id.
