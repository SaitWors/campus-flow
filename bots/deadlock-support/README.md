# Deadlock Contracts Support

Telegram-бот поддержки фанатского проекта Deadlock Contracts. Игрок выбирает тему и отправляет текст или фото. Оформленные обращения и дополнения приходят в личный чат одного владельца. Для вылетов игры и игровых блокировок бот сначала показывает официальные ссылки Steam и предлагает отдельно обратиться к команде проекта. Интерфейс доступен на русском и английском.

## Подключение в Campus Flow

1. Создай отдельного бота через [BotFather](https://t.me/BotFather) командой /newbot. Название для Telegram можно указать как **Deadlock Contracts Support**. Подбери свободный username с окончанием bot.
2. В GitHub открой **Actions → Deadlock Contracts support bot → последний успешный запуск**. В итогах задания Publish скопируй полный адрес образа вида ghcr.io/saitwors/campus-flow-deadlock-support@sha256:…. Campus Flow принимает публичные GHCR-образы. Если пакет опубликован впервые и остался private, владелец пакета должен открыть **Package settings → Change visibility → Public**. В образе находятся только файлы бота.
3. Открой [Campus Flow](https://mcg-mtuci.ru/) под аккаунтом владельца. В разделе **Управление → Боты** введи свежий код 2FA и выбери **Добавить бота**. Платформа — **Telegram**. Вставь образ в поле **Образ приложения**, токен из BotFather — в поле **Токен из BotFather**. Сохрани карточку и нажми **Запустить**.
4. Открой **Логи** на карточке. Когда появится строка **Owner setup**, скопируй команду /claim с кодом и отправь её боту из личного Telegram-аккаунта, который будет получать обращения. Код действует 20 минут и перестаёт работать после привязки. Если он истёк, перезапусти бота и используй новый код.
5. С другого Telegram-аккаунта отправь пробное обращение. Ответь на уведомление из аккаунта владельца, проверь доставку ответа, затем закрой обращение командой /close 1, подставив его номер.

Для запуска нужна версия Bot Runner с поддержкой постоянных томов data-v1. Если в логах говорится, что отсутствует BOT_DATA_DIR, обнови службу Runner по инструкции [Bot Manager](../../docs/BOT_MANAGER_RU.md). При обновлении образа редактируй существующую карточку бота, чтобы сохранить привязку владельца и очередь. Одна карточка соответствует одному Telegram-боту.

## Команды

| Игрок | Действие |
| --- | --- |
| /new | Открыть меню тем |
| /status | Посмотреть номер открытого обращения |
| /cancel | Отменить черновик |
| /language | Выбрать язык |

| Владелец | Действие |
| --- | --- |
| Ответ на уведомление бота | Отправить игроку текстовый ответ по этому обращению |
| /reply 12 текст | Ответить по номеру обращения |
| /inbox | Посмотреть до 30 открытых обращений |
| /close 12 | Закрыть обращение и уведомить игрока |

У игрока одновременно может быть одно открытое обращение. Новые тексты и фото добавляются к нему, пока владелец не закроет его. Номер, статус, связь с сообщениями Telegram и очередь доставки хранятся в SQLite в томе /data. После доставки тексты и фото доступны в истории Telegram. При временных сбоях бот повторяет отправку из очереди.

## Проверка

Из каталога бота выполни:

    python3 -m unittest discover -s tests -v

Тесты используют отдельную SQLite и имитацию Telegram. Реальные токены для CI не нужны.
